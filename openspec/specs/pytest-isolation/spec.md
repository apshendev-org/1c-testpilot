# pytest-isolation Specification

## Purpose
Каждый pytest-тест начинается в клиенте на начальной странице и не оставляет после себя созданных данных — как `УдалениеТестовыхДанных` в YAxUnit.

## Requirements

### Requirement: Сброс клиента к начальной странице
Система MUST предоставлять `Client.reset()`. Он закрывает все окна до начальной страницы, отменяет незавершённое редактирование строк и отвечает «Нет» на вопрос о сохранении. Если окна не закрылись, MUST вызвать ошибку с описанием оставшегося окна.

#### Scenario: Открыт модифицированный документ
- **WHEN** открыт документ с несохранёнными изменениями и редактируемой строкой
- **THEN** после `reset()` активна начальная страница, документ не записан

#### Scenario: Окно не закрывается
- **WHEN** окно отказывается закрываться
- **THEN** `reset()` вызывает ошибку с ключом и заголовком окна

### Requirement: Фикстура testpilot сбрасывает клиент перед тестом
Фикстура `testpilot` MUST вызывать `reset()` перед выдачей клиента тесту при любой `--tc-client-scope`. Ошибка сброса MUST проваливать тест на этапе setup.

#### Scenario: Тест после упавшего теста
- **WHEN** предыдущий тест упал с открытой формой документа, а `--tc-client-scope=session`
- **THEN** следующий тест получает клиент на начальной странице

### Requirement: Тест объявляет пользователя
Тест MUST объявлять основного пользователя маркером `@pytest.mark.testpilot(user="<логин>")` или параметром фикстуры `testpilot_user`. Фикстура MUST найти профиль с этим пользователем и той же базой, что у `--tc-profile`, и выдать клиент под ним. Без объявления — профиль `--tc-profile`.

#### Scenario: Основной пользователь из маркера
- **WHEN** тест помечен `@pytest.mark.testpilot(user="kfk_user")`
- **THEN** фикстура `testpilot` выдаёт клиент, вошедший как kfk_user

#### Scenario: Профиль не найден
- **WHEN** профиля с объявленным пользователем нет или их несколько
- **THEN** тест падает на setup со списком подходящих профилей

### Requirement: Переключение пользователя внутри теста
`testpilot.as_user("<логин>")` MUST вернуть клиент под этим пользователем: работающий — без перезапуска, иначе запущенный по профилю пользователя. Клиент каждого пользователя MUST сбрасываться при первом обращении в тесте. Клиенты разных пользователей MUST работать одновременно.

#### Scenario: Два пользователя в одном тесте
- **WHEN** тест создаёт документ под kfk_admin, затем открывает его через `testpilot.as_user("kfk_user")`, затем снова работает под kfk_admin
- **THEN** ни один клиент не перезапускается, оба остаются открытыми до конца теста

#### Scenario: Тот же пользователь в следующем тесте
- **WHEN** при `--tc-client-scope=session` следующий тест обращается к тому же пользователю
- **THEN** клиент не перезапускается, перед первым действием выполняется сброс

### Requirement: Учёт и удаление созданных данных
Фикстура `testpilot_data` MUST учитывать ссылки, переданные в `track(ref)`, ссылки из результата `create(code, parameters)` и ссылку активного окна из `track_window()`. После теста, в том числе упавшего, MUST удалить их в обратном порядке и вернуть ошибку teardown со списком неудалённых ссылок.

#### Scenario: Данные созданы кодом и через UI
- **WHEN** тест создаёт партнёра через `create(...)`, а документ — через форму с `track_window()`
- **THEN** после теста документ удалён раньше партнёра, запрос по этим ссылкам пуст

#### Scenario: Данные ролевого теста
- **WHEN** основной пользователь теста — ролевой без обработки
- **THEN** `create` и удаление выполняются через админ-клиент `--tc-profile` без указаний в тесте

#### Scenario: Объект уже удалён тестом
- **WHEN** учтённый объект к teardown уже не существует
- **THEN** он пропускается без ошибки

#### Scenario: Удаление не удалось
- **WHEN** удаление объекта вызывает исключение 1С
- **THEN** остальные объекты всё равно удаляются, teardown падает со списком неудалённых ссылок и текстами ошибок
