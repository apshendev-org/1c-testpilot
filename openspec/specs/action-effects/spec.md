# action-effects Specification

## Purpose
Действие само подтверждает свой эффект, ждёт и повторяет до таймаута: `ok` означает, что эффект наблюдается. Агенту не нужны отдельные чтения и параметры для обычной проверки.

## Requirements

### Requirement: ok только при подтверждённом эффекте
`click` и `input_text` MUST возвращать `ok: true` только при наблюдаемом ожидаемом эффекте. Иначе MUST вернуть `ok: false`, `code: effect_not_observed` и диагностику: ожидаемый эффект, активное окно и форма, тексты окон ошибок и сообщений пользователю, путь к слепку формы.

#### Scenario: Запись не прошла
- **WHEN** агент нажимает `ФормаЗаписать`, а обязательный реквизит не заполнен
- **THEN** ответ `ok: false`, `code: effect_not_observed`, `expected: "saved"`, в `messages` — текст сообщения 1С, в `snapshot` — путь к слепку

#### Scenario: Запись прошла
- **WHEN** агент нажимает `ФормаЗаписать` и документ записан
- **THEN** ответ `ok: true`, `effect: "saved"`, `ref` записанного объекта

### Requirement: Эффект стандартных команд известен движку
Для стандартных команд формы движок MUST сам определять ожидаемый эффект: Записать — записан; Провести — проведён; ЗаписатьИЗакрыть и ПровестиИЗакрыть — записан или проведён и форма закрыта; Закрыть, ОК, Выбрать — форма закрыта; Создать — открыта новая форма.

#### Scenario: Провести
- **WHEN** агент нажимает `ФормаПровести`
- **THEN** `ok: true` только если объект формы проведён

#### Scenario: Провести в клиенте без обработки
- **WHEN** у клиента нет обработки Testpilot, а админ-клиент той же базы доступен
- **THEN** движок читает `Проведен` объекта по `ref=` адреса окна запросом через админ-клиент; `ok: true` только если объект проведён

#### Scenario: Провести без обработки и без админ-клиента
- **WHEN** у клиента нет обработки и нет профиля админ-клиента той же базы
- **THEN** ответ `ok: false`, `code: admin_client_unavailable`, `profile` — имя нужного профиля

#### Scenario: Создать
- **WHEN** агент нажимает `ФормаСоздать` в списке
- **THEN** `ok: true` и `window` — ключ новой открытой формы

### Requirement: Эффект прочих действий — любое наблюдаемое изменение
Для прочих кликов движок MUST считать эффектом любое наблюдаемое изменение: активное окно, набор окон, форма, значения полей, сообщения пользователю, модифицированность.

#### Scenario: Клик по команде без стандартного имени
- **WHEN** агент нажимает произвольную команду формы и меняется значение поля
- **THEN** ответ `ok: true`, `effect: "changed"`, в ответе — что изменилось

### Requirement: Ожидание и повтор до таймаута
Если эффекта нет и нет ошибок 1С, движок MUST ждать эффект. Один повтор действия MUST быть только при полном наблюдении — движок читает значения полей формы (состояние формы от обработки Testpilot); без него повтора MUST NOT быть: «ничего не изменилось» не доказывает потерю нажатия, а повтор выполнил бы команду второй раз. Затем ждать до `timeout`. При сообщении об ошибке или окне ошибки MUST вернуть `ok: false` сразу, без ожидания.

#### Scenario: Медленная запись
- **WHEN** запись документа завершается через 3 с при `timeout` 30 с
- **THEN** ответ `ok: true` без повторного клика

#### Scenario: Окно ошибки
- **WHEN** после клика открывается окно ошибки 1С
- **THEN** ответ `ok: false` сразу, с текстом окна

#### Scenario: Значения полей не читаются
- **WHEN** состояние формы недоступно, команда меняет только значение поля, эффект не виден до `timeout`
- **THEN** `effect_not_observed`, `repeated: false`, команда нажата один раз

### Requirement: Исключение без видимого эффекта
`click` MUST принимать `expect="none"` для кнопок без наблюдаемого эффекта. С ним `ok: true` означает, что команда принята, а ожидания и повтора нет.

#### Scenario: Кнопка без эффекта
- **WHEN** агент нажимает кнопку с `expect="none"`
- **THEN** ответ `ok: true` сразу после принятия команды

### Requirement: input_text сравнивает значение по типу поля
После ввода движок MUST сравнить значение поля с введённым текстом по типу значения: число — численно в формате поля, дата — разобранной датой, булево — значением, строка — точным равенством. Если тип не прочитан, MUST сравнить строки, а при различии — принять ввод, когда текст и представление разбираются как одна дата формата сеанса. Сравнение по началу строки MUST NOT применяться.

#### Scenario: Число в формате поля
- **WHEN** в числовое поле введено «2», а поле показывает «2,000»
- **THEN** ответ `ok: true`

#### Scenario: Другое число
- **WHEN** в числовое поле введено «2», а поле показывает «20»
- **THEN** ответ `ok: false`, `code: value_mismatch`

#### Scenario: Строка с суффиксом
- **WHEN** в строковое поле введено «Протон», а поле показывает «Протон-2»
- **THEN** ответ `ok: false`, `code: value_mismatch`

#### Scenario: Тип поля неизвестен
- **WHEN** обработка Testpilot не подключена и тип значения не прочитан
- **THEN** сравнение — точное равенство строк

#### Scenario: Дата в поле компоновщика настроек
- **WHEN** в поле периода отчёта, тип которого не прочитан, введено «01.01.2026», а поле показывает «01.01.2026 0:00:00»
- **THEN** ответ `ok: true`, `verification: date_text`

### Requirement: Ввод в ссылочное поле — выбор с точным совпадением
Для поля ссылочного типа `input_text` MUST выбирать значение с точным совпадением представления. Если подходит несколько кандидатов или ни одного, MUST вернуть `ok: false` и список кандидатов.

#### Scenario: Группа вместо номенклатуры
- **WHEN** в ячейку номенклатуры вводится «1С:Бухгалтерия 8», а в списке есть группа «Программные продукты 1С» и элемент «1С:Бухгалтерия 8»
- **THEN** выбран элемент «1С:Бухгалтерия 8», ответ `ok: true`

#### Scenario: Неоднозначный ввод
- **WHEN** точное представление совпадает у двух элементов
- **THEN** ответ `ok: false`, `code: ambiguous_value`, `candidates` с обоими

### Requirement: Команда, закрывающая своё окно
Если первый кадр команды (`click`, `choose_row`) принят, а завершающий отклонён как «элемент недоступен» и окна элемента больше нет, движок MUST считать команду принятой и проверять её эффект как обычно. Если окно элемента открыто, отказ MUST остаться ошибкой `target_unavailable`.

#### Scenario: Выбрать в форме выбора
- **WHEN** агент нажимает «Выбрать» в форме выбора, и форма закрывается
- **THEN** ответ `ok: true`, `effect: "closed"`

#### Scenario: Выбор строки закрывает форму
- **WHEN** `choose_row` выбирает строку, и форма выбора закрывается
- **THEN** ответ `ok: true`, без `ActionError`

### Requirement: Текст окна ошибки в get_current_error
Если ошибки клиента нет, а активно окно `ErrorWindow`, `get_current_error` MUST вернуть его текст в `error` (сначала элементы `Message` и `ErrorInfo`), остальные надписи — в `details`, ключ окна — в `window`.

#### Scenario: Отказ записи
- **WHEN** `ПриЗаписи` устанавливает `Отказ`, после клика «Записать» активно `ErrorWindow`
- **THEN** `get_current_error` возвращает текст окна, а не `error: null`
