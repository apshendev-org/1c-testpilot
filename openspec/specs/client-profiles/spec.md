# client-profiles Specification

## Purpose
Много профилей подключения в одном файле (ib, daily, ролевые пользователи), порты тест-клиентов из общего пула машины и несколько живых клиентов одновременно. Одинаково для MCP, CLI и pytest.

## Requirements

### Requirement: Порт из пула машины
Профиль запуска MUST принимать `port_range: "<начало>-<конец>"`. Если порт не задан явно, движок MUST взять первый свободный порт с начала диапазона. Если свободных нет, MUST вернуть `code: port_pool_exhausted` со списком занятых портов.

#### Scenario: Первый свободный порт
- **WHEN** в диапазоне `30000-30999` заняты 30000 и 30001
- **THEN** клиент запускается на порту 30002

#### Scenario: Пул исчерпан
- **WHEN** все порты диапазона заняты
- **THEN** клиент не запускается, ответ `code: port_pool_exhausted`, `busy_ports` перечисляет занятые порты

### Requirement: Выбор порта и запуск под блокировкой машины
Выбор порта и запуск клиента MUST выполняться под блокировкой, общей для всех процессов testpilot машины. Файл блокировки лежит в каталоге машины, а не дерева. Блокировка MUST держаться, пока клиент не начнёт слушать порт или запуск не завершится ошибкой.

#### Scenario: Два запуска одновременно
- **WHEN** два процесса testpilot из разных деревьев одновременно запускают клиенты с одним диапазоном портов
- **THEN** клиенты получают разные порты

#### Scenario: Запуск не удался
- **WHEN** клиент завершился до открытия порта
- **THEN** блокировка снята, порт не записан в состояние

### Requirement: Несколько клиентов одновременно
Клиенты разных профилей, в том числе несколько ролевых, MUST работать одновременно. Запуск профиля MUST NOT останавливать клиенты других профилей.

#### Scenario: Два ролевых клиента
- **WHEN** запущен `роль:kfk_admin`, затем запускается `роль:kfk_user`
- **THEN** оба клиента работают на разных портах

### Requirement: Повторный запуск профиля переиспользует клиент
Запуск MUST записывать профиль, порт, pid и host в `.testpilot-clients.json` рядом с файлом профилей. Если для профиля есть запись с живым процессом, который слушает этот порт, запуск MUST подключиться к нему без нового процесса. Запись с завершённым процессом MUST считаться отсутствующей.

#### Scenario: pytest после client start
- **WHEN** `client start --profile ib` завершился, затем pytest запускается с `--tc-profile ib`
- **THEN** pytest подключается к порту из `.testpilot-clients.json` без нового запуска

#### Scenario: Процесс завершился
- **WHEN** запись указывает pid, которого уже нет
- **THEN** запись игнорируется, клиент запускается заново на свободном порту

### Requirement: MCP stdio с профилем в подключении
Один MCP-сервер (stdio) MUST обслуживать все профили файла `TC1C_PROFILES_FILE`. Профиль MUST передаваться параметром `launch_client`; работающий клиент профиля переиспользуется по `.testpilot-clients.json`.

#### Scenario: Ролевой профиль через MCP
- **WHEN** агент вызывает `launch_client` с `profile="роль:kfk_user"`, а клиент этого профиля уже запущен командой `client start`
- **THEN** сервер подключается к нему, ответ содержит `profile: "роль:kfk_user"`, `reused: true`

### Requirement: Запуск пользователя без права на внешние обработки
Если при запуске клиент сообщает, что пользователю запрещён запуск внешних обработок, движок MUST закрыть это окно и вернуть `ok: true`, `execution_ready: false` и `execution_reason` с текстом сообщения. Клиент MUST продолжить работу.

#### Scenario: Ролевой пользователь без права
- **WHEN** `client start --profile "роль:kfk_user"`, а пользователю запрещены внешние обработки
- **THEN** ответ `ok: true`, `execution_ready: false`, `execution_reason: "Текущему пользователю запрещен запуск внешних обработок."`, клиент работает

### Requirement: Подключение по порту без версии
Если `connect` вызван без `version`, а клиент отказал в рукопожатии с «Различаются версии клиента и сервера (A - B)», движок MUST один раз повторить рукопожатие с версией из отказа, которая не совпадает с отправленной. Явная `version` MUST NOT подменяться.

#### Scenario: Клиент из dev_ib.py client start
- **WHEN** клиент 8.3.27.2342 запущен `dev_ib.py client start`, агент вызывает `execute(calls=[{"action": "connect", "args": {"port": <порт>}}])`
- **THEN** подключение установлено, ответ называет платформу 8.3.27.2342

### Requirement: Подключение по профилю запуска
`connect(profile)` с профилем запуска MUST подключаться к живому клиенту из `.testpilot-clients.json`, только если подходящий клиент ровно один. Подходящий — клиент этого профиля или профиля той же базы, сервера и пользователя (с `port` — на этом порту). Ответ MUST содержать `reused: true` и профиль клиента. Ни одного — `profile_action_mismatch` с `suggested_call` `launch_client(profile)`. Несколько — отказ `client_ambiguous` со списком `running`. `connect` MUST NOT запускать процесс.

#### Scenario: Клиент запущен
- **WHEN** `client start --profile ib` завершился, агент вызывает `connect(profile="ib")`
- **THEN** MCP подключён к порту клиента `ib`, ответ `ok: true`, `reused: true`, `profile: "ib"`

#### Scenario: Клиент не запущен
- **WHEN** живого клиента профиля `ib` и его базы с тем же пользователем нет
- **THEN** отказ `profile_action_mismatch` с `suggested_call` `{"action": "launch_client", "args": {"profile": "ib"}}`, процесс не запущен

#### Scenario: Два подходящих клиента
- **WHEN** живы клиенты профилей `ib` и `ib-debug` с одной базой и пользователем
- **THEN** отказ `client_ambiguous`, `running` перечисляет оба профиля и порты, подключения нет
