# code-execution Specification

## Purpose
Исполнение произвольного кода BSL и запросов в сеансе тестируемого клиента через обработку Testpilot — для подготовки и проверки данных в тестах.

## Requirements

### Requirement: Код исполняется без фильтра идентификаторов
Система MUST передавать непустой код на исполнение без проверки идентификаторов по спискам запрещённых слов, включая `Выполнить`, `Execute`, `Вычислить`, `Eval`, `Записать`, `Удалить`. Переменные `TC1C_CODE_FORBIDDEN_WORDS` и `TC1C_CODE_ALLOWED_WORDS` MUST NOT влиять на исполнение.

#### Scenario: Запрос внутри кода
- **WHEN** тест вызывает `execute_code` на сервере с кодом `Результат = Новый Запрос("ВЫБРАТЬ 1 КАК Х").Выполнить().Выгрузить().Количество();`
- **THEN** код исполняется и возвращает `ok: true`, `result: 1`

#### Scenario: Запись объекта без настройки разрешённых слов
- **WHEN** `TC1C_CODE_ALLOWED_WORDS` не задана, а код вызывает `Объект.Записать()`
- **THEN** код исполняется без ошибки `forbidden_code`

#### Scenario: Старая переменная запрета игнорируется
- **WHEN** задано `TC1C_CODE_FORBIDDEN_WORDS=Сообщить`, а код вызывает `Сообщить("х")`
- **THEN** код исполняется без ошибки `forbidden_code`

### Requirement: Некорректный код отклоняется до отправки
Система MUST отклонять с `invalid_code`, ничего не отправляя в клиент, код, который не является непустой строкой или содержит незакрытый строковый литерал.

#### Scenario: Пустой код
- **WHEN** вызывается `execute_code` с `code="  "`
- **THEN** ответ `ok: false`, `code: invalid_code`, клиент не получает команд

#### Scenario: Незакрытая строка
- **WHEN** код содержит `Х = "abc;`
- **THEN** ответ `ok: false`, `code: invalid_code`

### Requirement: Клиент без обработки исполняет через админ-клиент
Для клиента без обработки Testpilot серверный код, запросы, метаданные и пользовательские функции MUST выполняться через админ-клиент той же базы (`base`, `server`): профиль, назначенный вызывающим (pytest — `--tc-profile`), иначе `ib`. Неподключённый админ-клиент MUST подниматься движком по профилю с переиспользованием по `.testpilot-clients.json`. Ответ MUST содержать `delegated_to`. Код в контексте `client` MUST NOT делегироваться.

#### Scenario: Запрос из ролевого клиента
- **WHEN** тест под `роль:kfk_user` без обработки вызывает `execute_query`
- **THEN** запрос выполняется админ-клиентом `ib`, ответ содержит строки и `delegated_to: "ib"`

#### Scenario: Админ-клиента нет
- **WHEN** у клиента без обработки нет профиля `ib` той же базы
- **THEN** ответ `ok: false`, `code: admin_client_unavailable`, `profile: "ib"`

#### Scenario: Клиентский код
- **WHEN** клиент без обработки вызывает `execute_code` с `context: "client"`
- **THEN** ответ `ok: false`, `code: client_code_unavailable`

### Requirement: Новый код после прежнего результата
Если прежнее исполнение не дождалось ответа, следующий вызов MUST сначала прочитать его результат, затем в том же вызове выполнить свой запрос и вернуть его ответ с прежним результатом в `previous_result`. Переданный код MUST NOT молча пропускаться.

#### Scenario: Teardown после сбоя
- **WHEN** `execute_code` истёк по сроку, затем teardown фикстуры вызывает `execute_code` с восстановлением константы
- **THEN** константа восстановлена, ответ `ok: true` и содержит `previous_result`

### Requirement: Исполнение не меняет активное окно
Исполнение кода, запроса, метаданных, функций и чтений формы MUST NOT активировать окно обработки Testpilot. Запрос MUST выполняться через форму запроса обработки, открытую над формой активного окна в режиме «Блокировать окно владельца» и закрываемую её кнопкой «Выполнить». После ответа MUST быть активна та же форма, а если код открыл форму — она; окно обработки MUST NOT получать активность и после закрытия этой формы.

#### Scenario: Запрос после действий с формой
- **WHEN** тест записал документ в открытой форме и сразу вызывает `execute_query`
- **THEN** запрос выполняется без `reset()`, после ответа активна та же форма документа

#### Scenario: Форма выбора из ячейки табличного документа
- **WHEN** форма выбора открыта из ячейки табличного документа (`begin_edit_current_area`), тест вызывает `find_rows`, затем `choose_row`
- **THEN** после `find_rows` активна форма выбора, после `choose_row` в ячейке выбранное значение, активна форма с табличным документом, а не `no_active_work_window`

#### Scenario: Код открывает форму
- **WHEN** `execute_code` выполняет `ОткрытьФорму` формы списка
- **THEN** после ответа активна открытая форма, а не форма-владелец запроса

#### Scenario: Код закрывает форму-владельца
- **WHEN** `execute_code` закрывает форму, над которой открыта форма запроса (например, «Информация при запуске» на старте)
- **THEN** ответ получен, окна ошибки нет, следующее исполнение проходит

#### Scenario: Нет рабочего окна
- **WHEN** активно окно обработки или активного окна нет (старт клиента)
- **THEN** запрос выполняется, форма запроса открывается над обработкой

### Requirement: Исполнение при модальном окне
Если активно модальное окно, блокирующее интерфейс (вопрос, окно ошибки), исполнение MUST отказывать с `modal_window_open` и подсказкой ответить на окно или закрыть его, ничего не открывая и не оставляя ожидающего запроса. После ответа на окно исполнение MUST проходить.

#### Scenario: Открыт вопрос
- **WHEN** поверх рабочей формы открыт вопрос «Да/Нет», тест вызывает `execute_code`
- **THEN** ответ `ok: false`, `code: modal_window_open`; после `answer_dialog` тот же `execute_code` выполняется, активна рабочая форма

#### Scenario: Окно ошибки
- **WHEN** открыто окно ошибки 1С, тест вызывает `execute_query`
- **THEN** ответ `ok: false`, `code: modal_window_open`; после `close_window` запрос выполняется

### Requirement: Незакрытая форма запроса
Если форма запроса осталась открытой (истёк срок, обрыв связи), следующее исполнение MUST сначала разрешить её: прочитать результат прежнего запроса, если он есть, иначе закрыть форму. Оставшаяся форма MUST NOT блокировать рабочее окно после ответа.

#### Scenario: Срок истёк
- **WHEN** `execute_code` истёк по сроку при открытой форме запроса, затем вызван `execute_query`
- **THEN** запрос выполняется, форма запроса закрыта, прежний результат — в `previous_result`, если он пришёл

### Requirement: Форма обработки без текста запросов
Окно обработки Testpilot MUST NOT содержать полей ввода запроса: код и запросы вводятся только в форму запроса и уходят вместе с ней. На форме обработки MUST оставаться только последний ответ и служебные сведения. Обработка без формы запроса MUST давать `helper_version_mismatch`.

#### Scenario: Старая обработка
- **WHEN** клиент запущен с `Testpilot.epf` прежней структуры (поля запроса на форме Helper)
- **THEN** `execute_code` отвечает `ok: false`, `code: helper_version_mismatch`
