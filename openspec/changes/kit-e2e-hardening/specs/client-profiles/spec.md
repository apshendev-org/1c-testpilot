# Spec Delta

## Purpose

Много профилей подключения в одном файле (ib, daily, ролевые пользователи) и общий порт у ролевых профилей: в каждый момент на порту жив один клиент. Одинаково для MCP, CLI и pytest.

## ADDED Requirements

### Requirement: Один клиент на порту
При запуске клиента по профилю, чей порт занят клиентом другого профиля, запущенным testpilot (MCP, CLI или pytest), движок MUST остановить прежний клиент и запустить новый. Если порт занят процессом, который testpilot не запускал, MUST вернуть `code: port_busy` с pid.

#### Scenario: Переключение роли
- **WHEN** на порту работает клиент `роль:kfk_admin`, запущенный `client start`, и запускается `роль:kfk_user` с тем же портом
- **THEN** клиент kfk_admin остановлен, запущен kfk_user

#### Scenario: Чужой процесс
- **WHEN** порт занят процессом, которого testpilot не запускал
- **THEN** запуск не выполняется, ответ `code: port_busy`, `pid`

#### Scenario: Тот же профиль уже запущен
- **WHEN** запускается профиль, клиент которого уже работает на этом порту
- **THEN** новый процесс не запускается, используется работающий клиент

### Requirement: Запущенный клиент виден другим процессам testpilot
Запуск клиента MUST записывать профиль, pid, host и port в файл состояния рядом с файлом профилей. Другой процесс testpilot MUST использовать эту запись, чтобы узнать профиль работающего клиента. Запись с завершённым pid MUST считаться отсутствующей.

#### Scenario: pytest после client start
- **WHEN** `client start --profile ib` завершился, затем pytest запускается с `--tc-profile ib`
- **THEN** pytest подключается к работающему клиенту без нового запуска

#### Scenario: Процесс завершился
- **WHEN** запись указывает pid, которого уже нет
- **THEN** запись игнорируется, клиент запускается заново

### Requirement: MCP stdio с профилем в подключении
Один MCP-сервер (stdio) MUST обслуживать все профили файла `TC1C_PROFILES_FILE`. Профиль MUST передаваться параметром `connect`/`launch_client`; на запуск действуют правила общего порта.

#### Scenario: Ролевой профиль через MCP
- **WHEN** агент вызывает `launch_client` с `profile="роль:kfk_user"` на сервере, где уже запущен `роль:kfk_admin`
- **THEN** прежний клиент остановлен, ответ содержит `profile: "роль:kfk_user"`
