# Design

## Context

- `app/_mcp.py` (`register`) публикует каждую группу `_ACTIONS` отдельным инструментом. Описание инструмента склеено из `_GROUP_DOC`, `_common_hint`, `_PARAM_NOTE`, `_EFFECT_NOTE` и документации каждого действия (`_fmt_action`). Схема — объединение параметров всех действий группы, `extra='forbid'`. Служебные группы (`SERVICE_TOOLS`) публикуются с сигнатурой своего единственного действия.
- Вызов идёт в `_dispatch_action(acts, group, kw)`. В конце ответ проходит `_deliver` → `format_result`: ссылки `ref`, сжатие, кодирование toon (по умолчанию). Скриншот превращается в `CallToolResult` с картинкой.
- Имена действий уникальны во всех группах: 169 действий в 17 группах, повторов нет. `_ACTION_GROUP` (имя → группа) уже есть, Python API (`Runtime.call(action, arguments)`) вызывает действие по одному имени.
- `TestpilotMCP.list_tools`/`call_tool` скрывают пользовательские функции, пока подключённая обработка их не регистрирует, и шлют `tools/list_changed` при смене видимости.

## Goals / Non-Goals

**Goals:**
- Схемы MCP — два инструмента, не длиннее 8000 символов вместе; документация действия приходит только по запросу.
- Поведение каждого действия — байт в байт как через прежнюю группу: тот же `_dispatch_action`.

**Non-Goals:**
- Исполнение кода (Python/JS) в `execute`: только список вызовов.
- Переименование действий, изменение аргументов и ответов.
- Изменение Python API, pytest-плагина, CLI `client`.
- Временный флаг прежней публикации: замена сразу (решение владельца).

## Decisions

1. **Отбор действий — прежний.** Цикл отбора `published` из `register` остаётся как есть. Из него получаются схема `execute` и каталог `search`, поэтому фильтры версии и настроек действуют одинаково. *Альтернатива*: отбирать заново в `search` — два места с одним правилом разойдутся.

2. **`execute` вызывает `_dispatch_action(published[group], group, {action, **args})`** с группой из `_ACTION_GROUP`, `connection_id` — в `kw`, как сейчас. Служебные действия (`SERVICE_TOOLS`) — тем же путём, что их нынешний `execute_dispatch`. *Альтернатива*: `Runtime.call` — он для Python API, ставит `_execution` и меняет `_deliver`; MCP должен остаться на своём пути.

3. **Проверка аргументов — до разрешения ссылок и выбора соединения.** Имена — прежний `_action_argument_error` (лишний или пропущенный аргумент → `invalid_arguments` с сигнатурой); `execute` зовёт его до `_dispatch_action`, чтобы лишний аргумент не дошёл до разбора `ref`. Типы — `pydantic.TypeAdapter` по аннотации каждого параметра из `_public_parameters(fn)`, нестрогий режим, как в прежней схеме группы; ошибка — `invalid_arguments` с сигнатурой. В схеме `execute` `args` — свободный объект: параметры действий в схему не попадают, иначе вернулся бы прежний объём. *Альтернатива*: модель pydantic на действие — имена параметров могут совпасть с атрибутами `BaseModel`.

4. **Шаги исполняются без кодирования, кодируется весь ответ.** `ref` ставит `_dispatch_connected_action_impl` (`_refs.present`), повторы окна сжимает `_response.compact_result`, оба — до `_deliver`. `format_result` только кодирует (`_response.respond`: сжатие адресов `ADDR_TOOLS` и toon). Флаг контекста `_batch` в `_deliver` отключает только кодирование: шаг получает `_response.prepare` (сжатие адресов без toon) или `Screenshot`. Так `$N.путь` разрешается по тем же полям, которые видит агент. В конце пачка `{ok, stopped_at?, steps}` один раз проходит `_response.respond`.

5. **Ссылки `$N.путь`.** Перед проверкой аргументов шага каждое строковое значение `args` (верхний уровень и вложенные списки/объекты), которое целиком совпадает с `^\$(\d+)\.(.+)$`, заменяется значением по пути: ключи объектов и индексы списков через точку. `$$…` → `$…` без подстановки. *Альтернатива*: шаблоны внутри строк (`"код $0.value"`) — для действий не нужны и усложняют экранирование.

6. **Скриншоты.** Шаг со `Screenshot` оставляет метаданные в `steps[i]`, PNG собирается в список изображений. `CallToolResult.content` = текст пачки + `ImageContent` по порядку шагов, в `steps[i]` — `image: <номер изображения>`.

7. **`search(query: str = "")`**:
   - пусто → группы: `_GROUP_DOC` (первая строка) и имена действий;
   - точное имя действия → `_fmt_action` + общие заметки группы (`_PARAM_NOTE`, `_EFFECT_NOTE` для действий с проверкой эффекта, `_common_hint`);
   - иначе слова запроса без учёта регистра ищутся в имени, группе и документации; ранжирование — сначала совпадение в имени, потом число совпавших слов; документация первых 8, остальные — именем.

   Пользовательские функции — только при `custom_visible()`.

8. **Схема `execute`**: `calls: list[{action: Literal[<имена>], args: dict = {}, connection_id: str | None}]`, `minItems=1, maxItems=20`. Описание — общие правила одним текстом: ок/эффекты (`_EFFECT_NOTE`), ссылки и `connection_id`, `$N`, остановка на отказе, «документация — `search`». Видимость пользовательских функций: `list_tools` подменяет `enum` в схеме `execute` по `custom_visible()`, `call_tool` отклоняет скрытое действие прежним сообщением.

9. **Ограничитель служебных вызовов.** Пачка, все шаги которой — `list_connections` или `disconnect(force=true)`, исполняется с `control_limiter`, остальные — с обычным. Пачка исполняется одним `anyio.to_thread.run_sync`: шаги одной пачки не перемешиваются с чужими.

10. **Подсказки.** Около 30 мест `tc_<группа>(action="x")` в `_runtime.py`, `tc1c.py`, `_mcp.py` (`_common_hint`, тексты ошибок, документация действий) переписываются на `x` или `x(параметр=…)`. Проверка — тест: в документации и сообщениях не осталось `tc_[a-z_]+\(`.

## Risks / Trade-offs

- [Модель шлёт неизвестные аргументы чаще, ведь схемы параметров нет] → отказ до отправки, в нём сигнатура действия: повтор с исправлением стоит один короткий шаг. Документация — через `search`.
- [Длинная пачка скрывает, где пошло не так] → остановка на первом отказе, номер шага в ответе, предел 20.
- [Пачка держит поток исполнения дольше одного вызова; служебный вызов в смешанной пачке ждёт] → служебные отдельной пачкой идут без очереди (решение 9).
- [BREAKING для всех агентов и документов, которые называют `tc_*`] → AGENTS.template.md — в том же релизе кита. Скиллы — отдельным PR после релиза: они доходят до проектов при слиянии в `master`, и скилл с `execute` раньше релиза сломал бы работу проектов на прежнем testpilot (порядок CLAUDE.md кита).
- [Клиенты MCP по-разному показывают несколько изображений в одном ответе] → Claude Code и pi уже получают изображение от `get_screenshot`; список `content` — стандарт MCP. Проверяется живой проверкой выпуска.
