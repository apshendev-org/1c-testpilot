## Context

Протокол Helper — JSON-запрос `{protocol, request_id, mode, context, …}` и ответ `{protocol, request_id, ok, result|error}` через поля формы (`ClientRequest`/`ClientResult`, `ServerRequest`/`ServerResult`) и кнопки `RunClient`/`RunServer`. Ввод в поле принимает только активное окно, отсюда `_focus_service` и возврат окна. Спайк spk_414937a75f: обработчик ожидания в модуле формы Helper выполняется при открытой форме выбора из ячейки, активность не уходит; ответ за 0,2–1,2 с при интервале 1 с.

## Goals / Non-Goals

**Goals:** код и чтения Helper не меняют активное окно; тот же протокол JSON; прежний путь — запасной.

**Non-Goals:** клиент на другой машине через файлы (нет общего каталога); замена протокола; канал через буфер обмена или расширение конфигурации (Vanessa VAExtension) — требует расширения без безопасного режима.

## Decisions

1. **Каталог обмена — на подключение.** testpilot создаёт `<tempdir>/testpilot-<connection_id>` и передаёт путь Helper при подключении (один запрос через поля: на старте формы выбора ещё нет). Несколько клиентов на машине (ib, daily) не мешают друг другу. После `stop_client` каталог удаляется.
2. **Файлы.** Запрос — `req-<request_id>.json`, ответ — `res-<request_id>.json`, Helper пишет через `.tmp` и `ПереместитьФайл` (атомарно для читателя). Запрос Helper удаляет до выполнения: повторный опрос не выполнит код второй раз.
3. **Опрос.** Повторяющийся обработчик — не меньше 1 с (idle-1: 0,5 с платформа отвергла). Чтобы не терять до 1 с на каждом чтении формы в `click`, проверяется однократный обработчик 0,1 с, переподключаемый в конце каждого опроса (задача 1.1). Не сработает — 1 с.
4. **Выбор режима.** Файлы — когда клиент запущен этим testpilot локально (`launched_pid`, `127.0.0.1`), каталог создан и Helper ответил `file_channel` в `capabilities`. Иначе — поля, как сейчас.
5. **Ожидание и сбой.** `timeout` вызова — общий для обоих режимов. Ответа нет к сроку — `execution_timeout` с `request_id`, как сейчас; следующий вызов сначала смотрит `res-<прежний id>.json` (`previous_result`). Файл запроса не забран за 5 интервалов опроса — канал считается неработающим, вызов возвращает `helper_channel_unavailable`, не переключаясь молча на поля (поля снова увели бы фокус).
6. **Форма.** В файловом режиме Helper скрывает поля обмена (`Видимость = Ложь`) и показывает строку состояния. В режиме полей после нажатия очищает поле запроса.

## Risks / Trade-offs

- [Синхронные файловые вызовы запрещены в конфигурации] → `SynchronousPlatformExtensionAndAddInCallUseMode` ≠ `Use`: Helper отвечает без `file_channel`, testpilot остаётся на полях. Асинхронные вызовы — отдельным изменением, если понадобятся.
- [Задержка опроса] → решение 3; измерение в задаче 1.1.
- [Чужой процесс пишет в каталог] → каталог в профиле пользователя клиента, код и сейчас выполняет тот, кто управляет клиентом; новой границы доверия нет.
- [Модальное окно 1С блокирует обработчик ожидания] → как и сейчас с полями: при открытом диалоге Helper недоступен, testpilot отвечает по диалогу.
