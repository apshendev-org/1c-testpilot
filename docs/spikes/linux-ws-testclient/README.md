# Спайк: Linux → тест-клиент 1С на WS

Вопрос: слушает ли порт TestClient (`-TPort`) не-loopback интерфейс и проходит ли
анонимный NTLM без SSPI (путь Linux).

Дата: 2026-11-22. WS: Windows, платформа 8.3.27.2342, клиенты запущены
`1c-testpilot client start` (порты 30000–30001). Linux: хост агентов bb вне корпоративной сети.

## Шаги

1. `listen.ps1` на WS: интерфейсы прослушивания портов 30000–30999.
2. `probe.py <host> <port>` с Linux: TCP, `Client.connect`, одно действие.
3. `probe.py <LAN-адрес WS> 30001 --no-sspi` на WS: тот же путь, что на Linux (SSPI отключён,
   рукопожатие — анонимный NTLM из `tc1c`), и для сравнения с SSPI.

## Итог

| вопрос | результат |
|---|---|
| интерфейс прослушивания | `0.0.0.0:30001` и `[::]:30001` — все интерфейсы; брандмауэр включён, входящие `NotConfigured` |
| TCP с Linux | `OSError: [Errno 101] Network is unreachable` — у хоста bb нет маршрута в сеть WS |
| анонимный NTLM без SSPI через LAN-адрес | `connect: ok`, сессия открыта за 0,2 с, `get_active_window` отвечает |
| с SSPI через LAN-адрес | то же |
| без `version` | `authentication handshake failed: Различаются версии клиента и сервера (8.3.27.1859 - 8.3.27.2342)` — версию надо передавать |

Вывод: протокол и анонимный NTLM готовы к удалённому подключению, блокер — сеть: с хоста
агентов WS недоступна. Прямой путь Linux→WS требует хоста в сети WS (или VPN); проверка
входящего соединения с другой машины через брандмауэр WS не проведена.
